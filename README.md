## Εισαγωγή

Η παρούσα εργασία αφορά τον σχεδιασμό και την υλοποίηση μιας βάσης δεδομένων για ένα φεστιβάλ μουσικής. Η βάση δεδομένων έχει σχεδιαστεί για να διαχειρίζεται πληροφορίες σχετικά με καλλιτέχνες, παραστάσεις, επισκέπτες, εισιτήρια, αξιολογήσεις και άλλα σχετικά δεδομένα.Επιπλέον, υλοποιήθηκε ένα σύστημα μεταπώλησης εισιτηρίων που επιτρέπει στους επισκέπτες να πωλούν και να αγοράζουν εισιτήρια μεταξύ τους.

Στόχος της εργασίας είναι η δημιουργία μιας αποδοτικής βάσης δεδομένων που να υποστηρίζει τις λειτουργικές απαιτήσεις του φεστιβάλ, καθώς και η ανάλυση της απόδοσης διαφόρων ερωτημάτων με τη χρήση διαφορετικών στρατηγικών βελτιστοποίησης.

## Σχεδιασμός Βάσης Δεδομένων

### ER Διάγραμμα

Το ER Διάγραμμα απεικονίζει τις οντότητες της βάσης δεδομένων και τις σχέσεις μεταξύ τους. 

Το πλήρες ER Διάγραμμα παρέχεται στο αρχείο `er.pdf`.

### Σχεσιακό Διάγραμμα

Το Σχεσιακό Διάγραμμα απεικονίζει τους πίνακες της βάσης δεδομένων, τα πεδία τους και τις σχέσεις μεταξύ τους.

Το πλήρες Σχεσιακό Διάγραμμα παρέχεται στο αρχείο `relational.pdf`.


## Ευρετήρια

Για τη βελτιστοποίηση της απόδοσης των ερωτημάτων, έχουν δημιουργηθεί διάφορα ευρετήρια στη βάση δεδομένων.

Τα ευρετήρια αυτά επιλέχθηκαν με βάση τα συχνά χρησιμοποιούμενα ερωτήματα και τις ανάγκες βελτιστοποίησης της βάσης δεδομένων.

## Triggers

Η βάση δεδομένων περιλαμβάνει διάφορους triggers που εξασφαλίζουν την ακεραιότητα των δεδομένων και αυτοματοποιούν συγκεκριμένες λειτουργίες.

Συνολικά, η βάση δεδομένων περιλαμβάνει 24 triggers που καλύπτουν διάφορες πτυχές της λειτουργικότητας και της ακεραιότητας των δεδομένων.


## Ανάλυση Ερωτημάτων 4 και 6

Στα ερώτηματα 4 και 6 αναλύθηκαν τρεις διαφορετικές στρατηγικές join:

1. **Nested Loop Join**: Χρησιμοποιεί την εντολή STRAIGHT_JOIN και τα πρωτεύοντα ευρετήρια.
2. **Hash Join (BNL)**: Χρησιμοποιεί την εντολή IGNORE INDEX για να αναγκάσει τον βελτιστοποιητή να χρησιμοποιήσει hash join.
3. **Merge Join**: Χρησιμοποιεί την εντολή FORCE INDEX για να αναγκάσει τον βελτιστοποιητή να χρησιμοποιήσει τα κατάλληλα ευρετήρια για merge join.

Η πλήρης ανάλυση των συγκεκριμένων ερωτημάτων βρίσκεται στο αρχείο 'report.pdf'

## Οδηγίες Εγκατάστασης και Χρήσης της Βάσης Δεδομένων

Ακολουθήστε τα παρακάτω βήματα για να εγκαταστήσετε και να χρησιμοποιήσετε τη βάση δεδομένων του project.

### Προαπαιτούμενα

Πριν ξεκινήσετε, βεβαιωθείτε ότι έχετε εγκατεστημένα τα παρακάτω:

-   **MariaDB Server**: Έκδοση 10.5 ή νεότερη.
-   **Git**: Για την κλωνοποίηση του repository.


### Βήμα 1: Κλωνοποίηση του Repository

Ανοίξτε ένα τερματικό ή γραμμή εντολών και εκτελέστε τις παρακάτω εντολές:

```bash
# Κλωνοποίηση του αποθετηρίου στη συσκευή σας
git clone https://github.com/eleninspl/NTUA-Databases.git

# Μετάβαση στον φάκελο που δημιουργήθηκε
cd NTUA-Databases
```

### Βήμα 2: Εγκατάσταση της MariaDB (αν δεν είναι ήδη εγκατεστημένη)
Επιλέξτε τις οδηγίες ανάλογα με το λειτουργικό σας σύστημα:
Για Ubuntu/Debian:

```bash
# Ενημέρωση λίστας πακέτων
sudo apt-get update
# Εγκατάσταση του MariaDB server και client
sudo apt-get install mariadb-server mariadb-client
```
Για Windows:
Κατεβάστε τον installer του MariaDB Server από την επίσημη ιστοσελίδα.
Εκτελέστε τον installer και ακολουθήστε τις οδηγίες εγκατάστασης. Κατά τη διάρκεια της εγκατάστασης, θα σας ζητηθεί να ορίσετε έναν κωδικό πρόσβασης για τον χρήστη root.

Για macOS (με Homebrew):

```bash
# Εγκατάσταση της MariaDB μέσω Homebrew
brew install mariadb
# Εκκίνηση της υπηρεσίας MariaDB
brew services start mariadb
```
### Βήμα 3: Δημιουργία και Ρύθμιση της Βάσης Δεδομένων
Συνδεθείτε στον MariaDB server ως χρήστης root (θα σας ζητηθεί ο κωδικός που ορίσατε κατά την εγκατάσταση):

```bash
# Σύνδεση στη MariaDB ως root
mysql -u root -p

# Στο περιβάλλον της MariaDB, εκτελέστε:
CREATE DATABASE festival;
CREATE USER 'festival_user'@'localhost' IDENTIFIED BY 'your_password';
GRANT ALL PRIVILEGES ON festival.* TO 'festival_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

### Βήμα 4: Εκτέλεση του Αρχείου Δημιουργίας Δομής (install.sql)
Αυτό το αρχείο δημιουργεί τους πίνακες, τα ευρετήρια, τους περιορισμούς (constraints) και τα triggers της βάσης δεδομένων festival. Εκτελέστε το από το τερματικό (όχι μέσα στο περιβάλλον της MariaDB), όντας στον φάκελο NTUA-Databases:
```bash
# Εκτέλεση του install.sql χρησιμοποιώντας τον χρήστη 'festival_user'
# Θα σας ζητηθεί ο κωδικός ('your_password') που ορίσατε στο Βήμα 3
 mysql -u festival_user -p < sql/install.sql   
```

### Βήμα 5: Φόρτωση Δεδομένων (load.sql)
Αυτό το αρχείο εισάγει τα αρχικά δεδομένα στους πίνακες της βάσης. Εκτελέστε το από το τερματικό:
```bash
# Εκτέλεση του load.sql χρησιμοποιώντας τον χρήστη 'festival_user'
# Θα σας ζητηθεί ξανά ο κωδικός του festival_user
mysql -u festival_user -p festival < load.sql
```

## Σύστημα Μεταπώλησης Εισιτηρίων

Υλοποιήθηκε ένα ολοκληρωμένο σύστημα μεταπώλησης εισιτηρίων με τα ακόλουθα χαρακτηριστικά:

1. **Λογική FIFO (First-In-First-Out)**: Οι αγοραστές και οι πωλητές εξυπηρετούνται με βάση τη σειρά προτεραιότητας, που καθορίζεται από την ημερομηνία ενδιαφέροντος και την ημερομηνία καταχώρησης αντίστοιχα.
2. **Αποφυγή Διπλών Εισιτηρίων**: Ένας αγοραστής δεν μπορεί να αγοράσει δεύτερο εισιτήριο για την ίδια παράσταση.
3. **Προτεραιότητα σε Συγκεκριμένα Εισιτήρια**: Οι αγοραστές που ενδιαφέρονται για συγκεκριμένα εισιτήρια εξυπηρετούνται πρώτοι.
4. **Ευελιξία στην Αντιστοίχιση**: Αν ο πρώτος πωλητής για μια κατηγορία και παράσταση δεν είναι διαθέσιμος, το σύστημα προσπαθεί να αντιστοιχίσει τον αγοραστή με τον επόμενο διαθέσιμο πωλητή.
5. **Ρεαλιστική Συμπεριφορά**: Μετά την πρώτη εκτέλεση, το σύστημα δεν εμφανίζει καθόλου αντιστοιχίσεις αν δεν προστεθούν νέες εγγραφές στους πίνακες `RESALE_BUYER_QUEUE` και `RESALE_SELLER_QUEUE`.


Το σύστημα υλοποιήθηκε ως stored procedure με όνομα `process_resale_matches()` και για να δείτε τα αποτελέσματα της διαδικασίας ακολουθήστε τις παρακάτω εντολές:

```bash
# Σύνδεση στη βάση 'festival' ως 'festival_user'
mysql -u festival_user -p festival

# Kλήση για προβόλη των αποτελεσμάτων 
MariaDB [festival]> CALL process_resale_matches();
```
